Start

Set up a machine

From a Linux machine with an NVIDIA card to ./alive check saying everything is in place. About an hour, most of it installing packages. Do this once.

What lives where

Four folders matter. Only the first is in git; the other three are yours, and can be links to any disk with room.

The order

1. System

Linux with an NVIDIA driver new enough for CUDA 12.8, then these tools:

sudo apt install ffmpeg git cmake build-essential
python3 -m pip install --user yt-dlp   # downloads the videos; any Python, it only has to be on PATH
curl -fsSL https://deno.land/install.sh | sh   # yt-dlp needs a JavaScript runtime for YouTube now
# Miniconda, into ~/miniconda3 (the default the scripts look in):
curl -LO https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh -b -p ~/miniconda3
# uv, a fast pip, for the three plain venvs:
curl -LsSf https://astral.sh/uv/install.sh | sh

2. Clone

git clone https://github.com/pavanteja295/alive && cd alive

3. Outside code

Three projects this builds on, each at the exact commit used, with our changes applied as patches: the face tracker (VHAP), the face renderer (STAvatar) and the voice model (F5-TTS).

bash env/setup_externals.sh

4. Environments

Six separate Python environments, because their libraries conflict. Each file in env/ is the exact package list. env/README.md has the full commands; in short:

~/.venvs/vc-f5voice training and servinguv venv --python 3.11, -r env/voice-f5.txt, then -e externals/F5-TTS
~/.venvs/vc-prepvoice data preparationuv venv --python 3.11, -r env/voice-prep.txt

The renderer's three CUDA extensions are diff-gaussian-rasterization, simple-knn and fused-ssim, under externals/stavatar/submodules/; env/README.md has the one pip install line that builds them. The answer engine and the viewer only need the system Python 3.11+ with python3 -m pip install --user anthropic.

You never activate an environment./alive, ./alive build and the answer engine run on the system python3, and every step calls its own environment's Python by path. The paths default to the ones in the table; if yours differ, set ENV_F5, ENV_PREP, ENV_STAVATAR or ENV_VHAP to the environment's folder. The stage pages show the Python to use when you run a step by hand.
Reusing environments from another projectThe tracker and voice environments install externals/vhap and externals/F5-TTS in editable mode, and F5 keeps its training data and saved models beside its own code. An environment installed from another checkout will train from that checkout's files, and can resume someone else's training run. Check with ~/.venvs/vc-f5/bin/python -c "import f5_tts; print(f5_tts.__path__)"; it must print a path inside this repository's externals/. If not: uv pip install --python <env>/bin/python --no-deps -e externals/F5-TTS (and the same for externals/vhap in the tracker's environment). Voice training refuses to start on a mismatch.
On a card other than the RTX 50 seriesset TORCH_CUDA_ARCH_LIST (for example 8.9 for an RTX 40) before the tracker and renderer first build their CUDA code.

The shared face assets

Every creator's face is the same MetaHuman rig reshaped to them, so a few files are built once from your rig and shared. The rig must be MetaHuman DNA version 2.5 (263 controls, 545 corrective shapes); older ones do not fit. Make a MetaHuman in Epic's MetaHuman Creator and export its face DNA; whose face it is matters little, because each creator's face is reshaped from it. face.dna and face_identity.dna are both read from data/face/assets/; the rig's arithmetic is taken from face_identity.dna. First build the DNA reader: bash env/setup_externals.sh --with-riglogic.

Build them in the table's order. The script's header shows the exact two commands for each --dump / --build pair.

Two files need Unreal Enginerig_names.npz and eye_mask.npz each read a file from an Unreal Engine 5.8 install with the MetaHuman plugin. Make them once on any machine that has it and copy them across; everything else here runs without Unreal. The rest of the table was rebuilt from scratch and matches the files the two example creators were trained with.

Check

./alive check drk
  ok    data/answers
  ok    externals/vhap
  ...
  MISSING checkpoints/drk/face/render/G4_teeth (mesh-to-render recipe, promote)

Every line that says MISSING names what to add and which recipe makes it. Before you have built anything, the creator's models will be missing; that is what building is for.
