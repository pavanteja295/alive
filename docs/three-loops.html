Three Loops

The answering system already had a loop. The benchmark split it in half to measure retrieval, and the harness built a third loop across the halves.

alive / engines / knowledge_style · 17 September 2026

The real system is one conversation

agent.py:229  run(question, …, max_turns=5)

The benchmark cut it in half

To measure retrieval on its own, the benchmark runs only the search half and throws the answer away, then hands the queries to a separate assembling call. Both halves are real code from the deployed path — but the conversation between them is gone.

Where the harness actually attaches

The harness is called after the queries exist. It never sees the question before retrieval has happened, so it cannot write the first queries — which is why its gap check writes its own, and writes them worse.

So the same job is being done three times

what this means for every number reported so far

Each arm labelled deployed k=6 ran the query writer at turns=1. The deployed default is max_turns=5.

So "the harness beats deployed" may partly mean "a loop beats no loop" — which was never in question. The comparison that matters, loop against loop, has not been run.

What is worth keeping

The filter is also the only piece whose mechanism was measured before its outcome, because retrieval is deterministic and set overlap against the oracle is a count rather than a judgement: 80 passages down to 30, every essential passage kept, precision 4.6×.

The order to settle it in

  • Open the two runs that already exist. bench_turns1.json and bench_turns4.json are loop 2 at one round and at four, already on disk. Scoring them on the four measures needs no generation and no new code, and it says what forcing the existing loop is worth against the harness's 79%.
  • Then decide where the loop belongs — one conversation that searches until satisfied, or staged calls between searches. Every intervention that gave the model less context has lost, five times out of five.
  • Latency is the real trade. Loop 1 is sequential calls with growing context; four rounds is unlikely to fit 60 seconds. The staged version fits in 38.
  • Keep the filter either way. It is orthogonal to which loop wins, and it is the one thing here with no counterpart in the system below.
