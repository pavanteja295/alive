Stage 6 · app/ and creators/<id>/live.env

The live app

Nothing is trained here. The app wires the five models together for one creator, and needs one settings file and one decision: what the creator does while waiting.

The settings file

Every creator has creators/<id>/live.env. Nothing in the code names a person; this file does.

What the viewer does between answers

Picking the resting pose (a person, or Claude, looks)

Raised hands, a lean or a look away read as the creator doing something, not waiting. A stillness scan cannot tell a hand held up and still from a hand at rest, so the scan proposes and someone chooses by looking.

  1. ./alive up <id>, then ask the face server for the six stillest 4-second windows:
    curl 'http://127.0.0.1:8730/calm?seconds=4&k=6'
    Every window is already front-facing.
  2. Draw each one as a sheet of 8 frames and look at all of them:
    curl -o c.jpg 'http://127.0.0.1:8730/calm_sheet?clip=<clip>&start=<start>&seconds=4'
  3. Choose the one that reads as listening: hands down or out of frame, upright, facing camera, nothing moving but breathing. The mouth does not matter; it is replaced. Rule out burned-in text.
  4. Write REST="<clip>@<start>" in live.env, with the reason and the runner-up in a comment. ./alive restart app.
  5. If none qualifies, pick a single front-facing, hands-down frame and set REST_HOLD=1: the body holds still and only the face moves. Dr K needed this: all 26 candidate windows had him gesturing.
  6. Look at the built loop at http://127.0.0.1:8800/idle before calling it done.

Claude Code can do this step: it can fetch the sheets, view them, and write the choice. That is how both creators' poses were picked.

The AI-generated label

The page always marks the picture AI-generated, and says under it: "The face, the voice and the answer are made by models from <name>'s public videos. <name> did not say this." Keep it. Someone who sees a clip of this cannot otherwise tell.
